# 2. Objective

Expose the existing local FastAPI application to the public Internet temporarily using a **Cloudflare Quick Tunnel**.

Target flow:

```text
Public Internet
      ↓ HTTPS
Cloudflare Quick Tunnel
      ↓
cloudflared
      ↓
http://127.0.0.1:8000
      ↓
FastAPI
      ↓
GET /orders/1111
```

The ticket succeeds when an HTTPS public URL generated by Cloudflare returns the same canonical deterministic payload as localhost.

---

# 3. Tunnel technology

Use:

```text
Cloudflare Quick Tunnel / TryCloudflare
```

Preferred command:

```bash
cloudflared tunnel --url http://localhost:8000
```

Cloudflare Quick Tunnels are intended only for development/testing and generate a temporary random public hostname.

Do NOT create:

* Cloudflare DNS records;
* a named production tunnel;
* Cloudflare Zero Trust configuration;
* a Cloudflare service;
* a permanent domain;
* production deployment infrastructure.

This tunnel is temporary runtime infrastructure only.

# 7. Public verification

Using the generated HTTPS hostname, verify from outside localhost:

### Canonical order

Request:

```text
GET https://<generated-host>/orders/1111
```

Required:

* HTTPS request succeeds;
* HTTP status `200`;
* response payload exactly matches:

```json
{
  "order_id": "1111",
  "status": "in_transit",
  "estimated_delivery": "2026-08-28"
}
```

### Unknown order

Request:

```text
GET https://<generated-host>/orders/9999
```

Required:

* HTTP status `404`;
* structured error remains equivalent to:

```json
{
  "detail": "Order not found"
}
```

### Determinism

Call the public canonical endpoint at least three times.

Verify that all successful response payloads are identical.
